# WinWin Care Coverage Pilot Checklist V1

Status: **POST-PILOT-01 CHECKLIST REVISION — NO PILOT-02 RESULT YET**

## 1. Purpose
Control 1–2 future pilot sessions that test the instrument, not B-01–B-04 closure.

## 2. Pilot vs Formal Test
Pilot checks instructions, leading risk, clues, recordability and duration. Pilot participants do not automatically enter formal data. Formal testing begins only after review, revisions and a material lock.

## 3. Pilot Participant IDs
Use `PILOT-01` and `PILOT-02`. Formal IDs start `P01`; never reuse or silently convert pilot IDs.

## 4. Material Version Check
Material: `CC-VAL-PILOT-V4`; state `SC-V2`; daypart `DP-V2`; consent `CN-V4`; category `CAT-V3`. Record actual date/version before use.

## 5. Pre-session Checklist
- [ ] Correct versions and exactly 4/10/1/16 cards.
- [ ] B-01 order assigned and recorded.
- [ ] Blank record, timer and participant code ready.
- [ ] Consent/privacy statement ready; recording choice separate.
- [ ] No answer key, enum, hypothesis, leading annotation or personal data visible.
- [ ] Participant-only render exported; this specification is not handed to participant.
- [ ] B01-C4 uses revised noncontradictory explanation.
- [ ] B-02 placement cards do not contain target daypart words.
- [ ] B-02 gap task uses the separate arrangement-fact card.
- [ ] B-01 confusion-source coding (`LABEL`/`EXPLANATION`/`STATE CONCEPT`/`UNCLEAR`) available.
- [ ] B-03 responsibility wording distinguishes ownership from mere verification.
- [ ] B-03 refusal says 「這次不接手」 and remains reason-free.
- [ ] Decline/Accept controls are parallel and equally styled.
- [ ] `需要時` is recurrence/applicability, not time.
- [ ] Zero, one or more contexts are permitted and recorded.
- [ ] `生活安排` is a qualitative hypothesis, not core truth.
- [ ] Seven core cards form the predefined denominator; nine boundary cards are qualitative.
- [ ] A09, A12 and A13 are excluded from core.
- [ ] Raw numerator/denominator and percentage are required together.
- [ ] B-03 uses the short WHAT / WHEN / ACCEPTING MEANS / CHOICE hierarchy.
- [ ] Missing-information question uses ordinary spontaneous wording.
- [ ] Five-activity exercise uses five neutral stepwise prompts, not a completed example.
- [ ] Sequential/module-by-module presentation prepared; full batch unavailable.
- [ ] Start/end and block timing fields ready, with `MISSING` allowed.
- [ ] Response-source field supports `VERBATIM`, `NEAR-VERBATIM`, `FACILITATOR PARAPHRASE`.

## 6. During-session Checklist
- [ ] Instructions understood without teaching.
- [ ] First responses reliably captured.
- [ ] Moderator avoided leading/correction.
- [ ] Questions were not needlessly repetitive.
- [ ] Cards did not reveal answers or become unrealistically easy.
- [ ] Task misunderstanding distinguished from semantic signal.
- [ ] Duration tracked.
- [ ] Live recording limited to first interpretation, essential response, critical flag, timing and feasible quote.
- [ ] B-01→B-03 and B-02→B-04 learning effects noted.
- [ ] Break/continue check completed after each module.

## 7. Post-session Checklist
- [ ] Quotes/paraphrases distinguished.
- [ ] Version/order/timing recorded.
- [ ] Instrument and product signals separated.
- [ ] Privacy disclosure minimized.
- [ ] Revision/retest need recorded.
- [ ] Early-stop location, voluntary reason if offered, and preceding conditions recorded.

## 8. Instrument-problem Classification
`INSTRUMENT_PROBLEM`: unclear instruction, answer leakage, missing material or unusable record field.

## 9. Product-signal Classification
`PRODUCT_SEMANTIC_SIGNAL`: participant understood the task but revealed a possible state, timing, consent or category problem. Pilot signal is not blocker-closing evidence by default.

## 10. Moderator-problem Classification
`MODERATOR_PROBLEM`: leading, premature correction, inconsistent probes, missed first response or exposed answer key.

## 11. Timing Check
Record total and block times. Allow approximately 40–55 minutes for the full pilot instrument. Use pilot timing to consider later formal reduction/counterbalancing; do not claim reliable 25–30 minute completion. Mark `TIMING_PROBLEM` if it exceeds feasible duration.

## 12. Recording Check
During the session confirm capture of first response, essential choice, critical issue, time and feasible quote. Complete detailed result codes and implications immediately afterward. Mark `RECORDING_PROBLEM` for lost or ambiguous evidence.

## 13. Material Revision Rules
Classify additional defects as `VISUAL_CLUE_PROBLEM` or `SCENARIO_PROBLEM`. Revise only supported instrument defects; preserve a change log and do not rewrite pilot records.

## 14. Version Increment Rules
Increment material/component version when participant-facing semantics, labels, card content, ordering constraints or task meaning changes materially. Formatting-only changes must still be logged. Never pool formal results across materially different versions without explicit separate analysis.

## 15. Repeat-pilot Rules
Repeat the affected block or full pilot when a material, moderator or recording defect could alter participant interpretation. Do not promote a defective version to formal use.

## 16. Formal-test Readiness Criteria
- [ ] Instructions understandable.
- [ ] No unintended answer clue.
- [ ] Moderator can administer without coaching.
- [ ] Record sheet captures evidence.
- [ ] Session feasible.
- [ ] No critical scenario/instrument defect open.
- [ ] No known M2 defect remains in the rendered material.

Meeting these criteria does not mean B-01–B-04 passed.

## 17. Formal Material Lock Checklist
- [ ] Material Version recorded.
- [ ] State Copy Version recorded.
- [ ] Daypart Version recorded.
- [ ] Consent Version recorded.
- [ ] Category Version recorded.
- [ ] Date locked and reviewer recorded.
- [ ] Open instrument defects = none.
- [ ] Participant/moderator files separated.
- [ ] Decision recorded as `FORMAL MATERIAL LOCK`.

This locks stimuli only, not Product Decisions.

## 18. Explicit Non-Closure Rule
Pilot completion cannot close any blocker, validate UX, freeze product decisions or authorize implementation. Pilot data are excluded from formal aggregates unless a later evidence gate explicitly justifies compatibility.

A voluntary stop is valid evidence, not participant failure.
