# Essential Care Tasks V0.1

> 專題工作名稱：家庭長期照顧中斷風險預警與照顧韌性支持系統
>
> 文件狀態：研究階段草案（V0.1）
>
> 注意：本文件不是正式量表，也不是醫療或長照資格判定工具。目的在於建立「照顧中斷情境模擬」需要檢查的照顧工作範圍。

## 1. 研究目的

本專題需要回答：

> 當主要照顧者暫時無法照顧 24 小時、72 小時或 7 天時，哪些照顧工作如果沒有被承接，會形成實際的照顧斷點？

因此，本專題不直接把完整長照評估量表搬進 App，而是從現有長照評估與服務內容中，挑出和「照顧能否持續」最直接相關的項目。

## 2. 官方依據摘要

衛福部長照相關評估與照顧問題清單包含進食、洗澡、穿脫衣物、大小便控制、上廁所、移位、走路、外出、備餐、用藥、溝通、皮膚照護、傷口、吞嚥、管路、其他醫療照護、安全疑慮與困擾行為等項目。

此外，喘息服務的實際內容也涵蓋如廁、沐浴、穿換衣物、口腔清潔、進食、服藥、翻身、拍背、上下床及使用輔具等照顧工作。

這表示上述項目確實屬於長照現場可能需要他人承接的照顧活動，但是否全部需要納入本 App，仍需依「是否會形成照顧中斷」做篩選。

## 3. 本專題的篩選原則

一項照顧工作若要放進「中斷情境模擬」，至少應符合下列其中一項：

1. 若無人處理，可能在短時間內影響基本生活或安全。
2. 明確需要另一個人協助，而非被照顧者可完全自行完成。
3. 有固定或相對明確的時間需求，可形成照顧空窗。
4. 需要特定能力、知識、設備或正式服務才能接手。
5. 主要照顧者離開後，可能因無替代者而直接失效。

不符合上述條件、與中斷情境關聯較低的資料，不應因「完整」而強迫使用者填寫。

## 4. 第一版分類

### A. 核心必查項目

這些項目適合作為大多數家庭第一次建立照顧結構時的核心盤點。

| 照顧工作 | 為何和中斷直接相關 | 模擬時需要知道什麼 |
| --- | --- | --- |
| 進食／餐食 | 每日重複且通常有固定時段 | 是否可自行進食、誰準備、誰協助、是否需餵食 |
| 飲水／基本營養 | 部分失能者需要他人提醒或協助 | 是否需協助、是否存在吞嚥或特殊限制 |
| 用藥 | 常有固定時間，交接錯誤風險高 | 誰準備、誰提醒／協助、替代者是否知道正確方式 |
| 如廁／排泄照護 | 若需他人協助，無人接手可能形成明顯空窗 | 是否需陪同、清潔、更換尿布或其他協助 |
| 移位／上下床 | 常需要人力或技巧 | 是否需一人／多人協助、輔具、替代者是否會操作 |
| 基本移動 | 影響進食、如廁、就醫與日常活動 | 是否能自行走動、需要攙扶、輪椅或其他協助 |
| 夜間照顧 | 正式服務與家人支援常可能出現時段落差 | 是否需翻身、如廁、移位、巡視或其他夜間協助 |
| 緊急聯絡／突發事件處理 | 主要照顧者不在時需有人知道如何處理 | 誰能聯絡、誰能到場、是否知道必要資訊 |

### B. 條件式必查項目

只有當被照顧者具有該需求時才展開，避免所有人都填一大份問卷。

| 照顧工作 | 啟用條件例 | 需要確認的備援能力 |
| --- | --- | --- |
| 洗澡 | 需要他人協助沐浴 | 替代者是否能安全完成、是否已有居服支援 |
| 穿脫衣物／個人清潔 | 無法自行完成 | 誰可以協助，多久需要一次 |
| 備餐 | 無法自行準備餐食 | 家人、送餐、居服或其他替代方案 |
| 吞嚥照護 | 有吞嚥困難或特殊飲食需求 | 食物質地、進食協助與替代者知識 |
| 翻身／擺位 | 長時間臥床或有壓傷風險 | 夜間及白天是否有人能執行 |
| 傷口／皮膚照護 | 有傷口、壓傷或固定護理需求 | 是否需護理專業或經訓練家屬 |
| 管路照護 | 鼻胃管、導尿管、氣切、造瘻等 | 替代者是否具備照護能力，是否需專業服務 |
| 呼吸／其他醫療照護 | 氧氣、抽痰等特定需求 | 是否有合適人力、設備與專業支持 |
| 認知／困擾行為照護 | 失智、遊走、日夜顛倒、拒絕照護等 | 替代者是否了解應對方式，是否能獨自照顧 |
| 外出／就醫 | 有固定就醫、復健、透析等需求 | 誰陪同、交通是否可用、資訊是否交接 |
| 安全看視 | 無法安全獨處 | 哪些時段一定要有人在場 |

### C. 暫不列為「中斷模擬核心」的項目

下列項目可能很重要，但目前不宜全部直接放進 24／72 小時模擬核心：

- 財務處理
- 購物
- 家務
- 社會參與
- 一般電話使用
- 非急迫性的居家環境改善
- 情緒狀態本身

理由不是這些不重要，而是它們多數不一定在短期主要照顧者離開後立即形成「必要照顧工作無人承接」。

但若特定家庭把其中某項視為不可中斷需求，後續可允許自訂加入。

## 5. 不建議直接照搬 ADL／IADL 的原因

ADL（Activities of Daily Living，日常生活活動）與 IADL（Instrumental Activities of Daily Living，工具性日常生活活動）非常適合評估生活功能，但本專題的研究問題不同。

我們不是只問：

> 被照顧者會不會做這件事？

而是要問：

> 如果主要照顧者不在，這件事在需要發生的時間點，是否仍有人能安全完成？

因此，相同的 ADL 狀態可能產生不同的中斷風險。

例如兩位長輩都需要協助如廁：

- 家庭 A：女兒與居服可以完整接手。
- 家庭 B：只有主要照顧者會協助，夜間沒有替手。

兩人的「如廁功能」可能相同，但家庭 B 的照顧中斷風險明顯不同。

## 6. 本 App 應該記錄「照顧工作」而不是只記錄「疾病」

初步建議的資料邏輯：

```text
照顧需求
  ↓
形成一項具體照顧工作
  ↓
這項工作什麼時間需要發生？
  ↓
目前主要由誰執行？
  ↓
是否需要特殊能力／設備？
  ↓
主要照顧者離開後，誰能接？
  ↓
替代者的可用時間是否覆蓋？
  ↓
形成：已覆蓋／待確認／目前無備援
```

例如：

```text
需求：無法自行移位
照顧工作：床到輪椅移位
時間：07:30、13:00、21:30
主要照顧者：配偶
必要能力：一人協助＋移位技巧
替代者：女兒
女兒可支援：18:00 後
結果：07:30 與 13:00 形成照顧斷點
```

這比只記錄「ADL 移位需要協助」更能回答本專題的核心問題。

## 7. 目前的 MVP 建議

第一版 Prototype 不需要支援全部 34 類長照問題。

建議優先處理：

1. 進食／備餐
2. 用藥
3. 如廁／排泄
4. 移位／基本移動
5. 洗澡（條件式）
6. 夜間照顧
7. 安全看視
8. 外出／就醫（有固定需求時）
9. 管路／特殊醫療照護（條件式）
10. 自訂必要照顧工作

這 10 類目前只是「原型範圍建議」，仍需透過後續使用者研究或專家訪談確認，不宣稱為正式標準。

## 8. UX 原則

為降低照顧者填寫負擔，未來不應一次顯示所有可能問題。

可採用分支式問法，例如：

```text
被照顧者目前是否需要他人協助進食？
├─ 否 → 不建立進食協助工作
└─ 是
   ├─ 通常一天需要幾次？
   ├─ 哪些時間？
   ├─ 現在誰協助？
   └─ 還有誰可以接手？
```

這種方式比直接呈現完整醫療／長照量表更符合一般家庭使用情境。

## 9. 尚未解決的問題

目前仍需要進一步驗證：

1. 哪些工作一定要放在所有家庭的初始盤點？
2. 哪些需求可以合併，避免問卷太長？
3. 夜間照顧應如何細分，才不會過度複雜？
4. 「可獨處多久」是否應成為單獨的重要欄位？
5. 特殊醫療照護應記錄到什麼程度，才能兼顧安全與資料最小化？
6. 備援者的「會做」應如何驗證，而不是只靠本人勾選？
7. 正式長照服務應如何轉換成時間覆蓋資料？
